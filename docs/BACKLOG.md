# TrailViewer backlog

## 附件图片导出性能与入口优化

**状态：已完成**  
**记录日期：2026-11-18**

### 目标

降低大量内置图片和 HTTPS 外链图片的导出等待时间，并把“只要内置图片”的快速路径独立出来。

### 已确认方案

1. 内置图片改由宿主直接复制当前文件根目录内的图片，避免
   `fetch → Base64 → 分块 WebMessage → 宿主解码`。Data URI 继续使用现有分块传输。
2. HTTPS 外链使用最多 3 个并发下载任务；同一域名在单次导出中只做一次安全解析。
3. 外链单张请求超时缩短到 8–10 秒，失败只影响当前图片，不阻塞剩余队列。
4. 最终文件命名和重名检测继续串行，确保并发下不覆盖文件。
5. 把单一导出入口拆为 **导出全部图片** 和 **导出内置图片**。
6. 进度区分已保存、正在下载和失败数量；关闭预览时取消未开始的外链任务。

### 待定

- 无。云图标、文件夹图标、双入口、本地直拷和外链三路并发均已实现。

### 验收

- 内置图片不再产生整图 Base64 和 WebMessage 流量。
- 同域名外链按有限并发执行，失效链接快速结束。
- 两种导出入口都保留数量提示、进度、成功/失败汇总和无障碍名称。
- 覆盖路径穿越、重名文件、外链失败隔离、150 张图片批次和 KMZ 导出。

## 附件图片导出续传

**状态：已完成**  
**记录日期：2026-11-18**

- 在 `<文件名>-photos` 内维护隐藏清单 `.trailviewer-photo-export.json`。
- 清单绑定原轨迹路径、大小和修改时间；源文件变化后旧清单自动失效。
- 每次成功写入一张图片后原子更新清单。
- 重新导出前由宿主返回已完成项目，页面不为已存在图片做本地复制、Data URI 传输或外链下载。
- 被删除或大小异常的图片会自动重新调度。
- 纯续传时显示“新增 0 张 · 跳过已完成 N 张”。

## 叠加图导出一体化与两批优化

**状态：已完成**  
**记录日期：2026-11-18**

- 叠加图导出设置改为工具箱内部页面，复用统一标题栏、半透明表面、返回和关闭逻辑。
- 删除 `X` / `Shift+X` 导出快捷键。
- 普通轨迹写入路线名称和日期，指标顺序改为距离、总用时、累计上升、最高海拔、运动均速。
- 路网文件显示文档名称、路线总长和轨迹段数，不绘制起终点，不生成用时、速度或海拔统计。
- 三个版式按钮增加尺寸和适用场景提示。
- 浏览器测试覆盖工具箱内导出页、名称与日期、指标顺序、路网语义和快捷键移除。
- 第二批增加低分辨率实时预览，跟随版式、墨色和底衬变化。
- 墨色与底衬按钮增加适用背景和透明度说明。
- 输出文件名包含版式、墨色和底衬，同版式的不同样式不再互相覆盖。
- 导出完成后保持工具箱和设置页打开，支持连续导出不同版式。
- 预览画布增加明暗双层边界，明确显示实际图片范围和比例。
- 叠加图导出与附件图片导出改用“地图折页”和“照片堆叠”两个不同图形，避免工具栏辨识混淆。
- 坐标地图提示与最近结果卡显示点位海拔；吸附点使用源轨迹海拔，自由点显示无数据状态。
- 工具箱主菜单采用 2×2 快捷工具格，四项高频工具一键进入，轨迹天气保留为下方完整功能条。
